# 시변 저궤도 위성망 경로 최적화

저궤도(LEO) 위성망에서는 위성 간 링크가 궤도 운동에 따라 생기고 끊어진다.
이 저장소는 이런 시변 위성망에서 통신 세션이 끊기지 않도록 경로를 정하는 문제를
강화학습(PPO-GCN), 수리최적화(CP-SAT), LLM 기반 최적화로 다룬다.

## 연구 흐름

| 단계 | 문제 설정 | 방법 | 상태 |
|---|---|---|---|
| 1 | 패킷을 한 홉씩 전달하는 모델. 링크의 남은 접촉 시간을 반영한 선제적 라우팅 | GCN-PPO | 석사 학위논문, 한국항공우주학회 학술대회 구두발표(2026.06) |
| 2 | 세션 단위 모델. 3차원 Walker-Delta 궤도(위성 1,584개), 위성당 고정 터미널 2개와 재구성 터미널 1개, PAT 설정 지연 20초 | PPO-GCN, 기준 방법 5종 | WCNC 2027 투고(심사 중). 이 저장소의 환경 코드 |
| 3 | 운영자가 텍스트로 주는 조건(위성 정비, 혼잡 지역, 통과 금지 지역, PAT 재지향 상한, 지연 상한)을 지키는 세션 경로 | LLM 라우팅 에이전트(추론만, 학습 없음), Python 도구, 검증된 CP-SAT 모델 | 2단계와 같은 환경과 테스트 요청에서 평가 |

## 2단계 결과 (WCNC 2027 투고 논문 표 II, III)

고정된 테스트 요청 3,600개(지상 쌍 3개 × 도착 시각 240개 × 유지 시간 X = 20, 60, 180, 300, 600초)에서,
경로를 세운 뒤 X초 동안 끊김 없이 유지한 비율(strict session completion)이다.

| 방법 | 세션 완주율 |
|---|---:|
| Dijkstra | 51.14% |
| PRP | 72.39% |
| Cost-Greedy | 80.64% |
| Adapted ISASR | 82.11% |
| Lifetime | 83.53% |
| **PPO-GCN** (시드 3개 평균) | **92.56%** (표본 표준편차 1.66%p) |
| Feasibility witness (참고 기준) | 100% |

요소 제거 실험(시드 0, 전체 모델 94.44%): 남은 접촉 시간 특징을 빼면 78.22%, PAT 설정 비용 항을
빼면(물리적 설정 지연 20초는 그대로) 83.64%다.

Feasibility witness는 배포할 수 있는 방법도, 최적해도 아니다. 같은 터미널과 PAT 가정에서 각 요청을
완주할 수 있는지 확인해서, 정책의 실패와 물리적으로 불가능한 요청을 구분하는 용도로만 쓴다.

전체 표와 통계 검정은 [`results_ppo_gcn/priority_evidence_2026-09-04/RESULTS.md`](results_ppo_gcn/priority_evidence_2026-09-04/RESULTS.md)에 있다.

## 3단계 결과: 텍스트 운영 조건을 지키는 LLM 라우팅

PPO-GCN과 기준 방법은 운영자가 텍스트로 주는 조건을 읽지 못한다. 3단계는 2단계와 같은 시뮬레이터와 같은
테스트 요청(3,600개 중 지상 쌍 3 × 유지 시간 5 × 도착 시각 12 = 180개)에서 LLM이 조건을 반영하게 한다.
LLM은 Dijkstra 경로와 그 주변 1홉 위성 정보를 받아 지상국 간 경로 전체를 고친다. 도구 조건에서는 Python 도구
3개(경로 검사, 조건부 경로 탐색, 제출)를 쓴다. 도구는 운영자 텍스트를 읽지 않으므로 텍스트를 도구 인자로 바꾸는
일은 LLM이 한다. 모델은 OpenAI API(temperature 0)로 추론만 하고 학습하지 않는다. 조건 준수는 세션 동안 기록된
경로를 10초 간격으로 따라가며 잰다.

**조건 하나씩 (180개, LLM = GPT-4o mini)**

| 운영 조건 | 지표 | Dijkstra | PPO-GCN | LLM | LLM + 도구 |
|---|---|---:|---:|---:|---:|
| 없음 | 세션 완주율 | 59.4% | 93.0% | 58.9% | 78.9% |
| 위성 정비 공지(시뮬레이터는 미리 모름) | 세션 완주율 | 4.4% | 77.0% | 2.8% | **86.7%** |
| 혼잡 지역은 가능하면 피함 | 그 지역 위에 있던 시간 | 91.7% | 94.2% | 91.8% | **17.9%** |
| 통과 금지 지역 | 그 지역 위에 있던 시간 | 90.6% | 95.7% | 91.3% | **41.4%** |
| PAT 재지향(새 링크) 상한 | 상한을 넘은 세션 | 100% | 99.4% | 99.4% | **22.8%** (완주 96.7%) |
| 단방향 지연 상한 | 상한을 넘은 시간 | 18.2% | 52.3% | 21.6% | **12.5%** (완주 83.9%) |

위성 정비에서 정비 위성은 Dijkstra 경로에서 골랐다. PPO-GCN은 경로가 Dijkstra와 달라 86%의 세션에서 우연히 그
위성을 피했고, 첫 경로가 그 위성을 쓴 세션의 완주율은 1.8%다. LLM + 도구는 공지를 읽고 100% 피했다
([`results_llm/maintenance_exposure.md`](results_llm/maintenance_exposure.md)).

**조건 여러 개를 한꺼번에 (20개: 링크 수명 + 통과 금지 지역, 지연 상한, 새 링크 상한 중 2~3개)**

| 방법 | 요청 시각에 조건 모두 준수 | 세션 중 금지 지역 위반 | 세션 완주율 |
|---|---:|---:|---:|
| 기준 방법 5종, PPO-GCN | 0~5% | 100% | 65~98% |
| LLM 경로 수정 + 도구 (GPT-4o mini) | 15% | 60% | 80% |
| LLM이 CP-SAT 코드를 직접 작성 (GPT-4o) | 0% | 100% | 65% |
| **LLM이 검증된 CP-SAT 모델의 조건을 채움 (GPT-4o)** | **100%** | **0%** | **85%** |
| LLM이 검증된 CP-SAT 모델의 조건을 채움 (GPT-4o mini) | 95% | 0% | 85% |

조건이 여러 개 겹치면 경로를 찾는 일이 자원 제약이 여러 개인 최단 경로 문제가 되어, 조건 하나씩 다루는 도구로는
15%만 모두 지켰다. LLM에게 CP-SAT 코드를 처음부터 쓰게 하면 GPT-4o도 20개 중 하나도 실행 검사를 통과하지 못했다
(시간 초과와 API 오용). 그래서 LLM은 텍스트를 해석해 검증된 CP-SAT 모델의 조건 값을 채우고, 최적화와 규칙 준수는
solver가 맡는 구조로 설계했다. 두 모델 모두 20개의 조건을 모두 맞게 읽었고, 남은 1개(mini)는 CP-SAT가 20초 안에
해를 찾지 못한 경우다. 요청당 LLM 비용은 약 0.001달러다.

실험 규약, 개발 기록, 모든 결과표는 [`docs/LLM_ROUTING.md`](docs/LLM_ROUTING.md)와 [`results_llm/`](results_llm/)에 있다.

## 구성

```text
leo_session/       위성망 환경: 궤도, 접촉 구간, 초기 토폴로지, 기준 경로 방법, 세션 실행, 보상
ppo_gcn/           PPO-GCN: 희소 그래프 관측, actor-critic 모델, 학습
scripts/           접촉 구간 생성, 기준 방법 실행, 학습, 평가, 표와 그림 생성, 재현 검증
tests/             궤도, 토폴로지, 경로, 보상 검사
cache/             접촉 구간 캐시
results_paper/     기준 방법 결과(테스트 3,600개), PAT 설정 지연 민감도, feasibility witness
results_ppo_gcn/   PPO-GCN 체크포인트와 평가 결과(시드 0/1/2, 요소 제거 실험)
llm_routing/       LLM 라우팅 에이전트: 입력 구성, 경로 검증, 도구, 준수 평가, CP-SAT 모델, 코드 실행 격리
multisession/      여러 세션 확장 모델의 CP-SAT 정식화와 운영 조건(지역 범위 등) 정의
results_llm/       LLM 실험의 조건 시나리오, 실행 기록, 결과표
docs/              설계, 보상, 평가 지표, 실험 절차, 참고문헌, 재현 방법, LLM 실험 규약
```

## 실행

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

.venv/bin/python -m pytest -q tests                      # 테스트
.venv/bin/python scripts/verify_reproduction_bundle.py   # 입력, 체크포인트, 핵심 결과 검증
.venv/bin/python scripts/run_cpu_baselines.py            # 기준 방법 시험 실행(작은 규모)
```

테스트 요청 3,600개 전체 재현과 PPO-GCN 학습 명령은 [`docs/REPRODUCE.md`](docs/REPRODUCE.md)에 있다.
LLM 실험은 `.env`에 `OPENAI_API_KEY`를 두고 실행하며, 명령은 [`docs/LLM_ROUTING.md`](docs/LLM_ROUTING.md)에 있다.
설계 전반은 [`docs/TECHNICAL_OVERVIEW_KO.md`](docs/TECHNICAL_OVERVIEW_KO.md)와 [`docs/DESIGN.md`](docs/DESIGN.md)에 있다.
